# G+G — вход для AI-разработчика

Перед работой прочитай:

1. `docs/PROJECT_MASTER.md` — единственные канонические правила разработки;
2. `docs/AI_RULES_INVENTORY.md` — найденные конфликты и исторические источники;
3. относящиеся к задаче architecture/security/decision документы и фактический код.

Этот файл не содержит отдельного backlog, статуса ветки, числа тестов или
указаний самостоятельно продолжать разработку. Такие сведения быстро устаревают.

Короткие обязательные границы:

- выполняй только текущую прямую задачу владельца;
- одна проблема — один небольшой обратимый diff;
- не меняй работающую подтверждённую функцию без воспроизводимого дефекта;
- не считай документацию, mock, кнопку, typecheck или старый PASS доказательством
  реального пользовательского сценария;
- не удаляй и не перезаписывай чужие незакоммиченные файлы;
- не печатай cookies, токены, browser storage, profile contents и приватные данные;
- не обходи CAPTCHA/challenge и не запускай повторные provider probes;
- renderer не получает прямой Node/filesystem/shell доступ;
- Markdown, code fence и обычный текст никогда не разрешают исполнение;
- Secure Code Runtime остаётся отдельным proposal и не реализуется без прямой
  команды владельца, ADR и отдельной ветки;
- focused check используется для микрошагa; полный check/package/smoke/UAT — только
  на согласованном checkpoint, в CI, перед release или по отдельной команде;
- `VERIFIED_USER` ставится только после ручного подтверждения владельца.

Если документы расходятся, не исправляй попутно код. Зафиксируй конфликт и следуй
приоритету: текущая команда владельца → `docs/PROJECT_MASTER.md` → scoped
architecture/security decisions → исторические status/plan документы.
